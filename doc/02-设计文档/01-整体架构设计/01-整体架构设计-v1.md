# dsh-ide 整体架构设计 v1

- 文档定位：定义「做什么」，是分期开发计划与执行步骤的唯一上游依据，不直接用于编码。
- 适用宿主：DeepSeek Harness `0.2.1-rc.3`（本机 `dsh --version` 实测），profile 为 `desktop`。
- 设计原则：不依赖任何第三方 DSH 插件，宿主自有能力能用的全部复用；插件自身零运行时第三方依赖（编辑器与高亮按需懒加载进独立 chunk）。

---

## 一、目标与范围

### 1.1 目标

在 DSH 内提供一个可完全掌控的 IDE 工作台，覆盖 IntelliJ IDEA 的日常编码闭环：

浏览 → 打开 → 编辑 → 保存 → 看差异 → 管理版本 → 运行命令 → 启动项目 → 定位问题。

### 1.2 用户场景

1. 打开任意会话，工作台出现在主区或右侧栏，根目录取该会话的工作目录。
2. 在项目树里逐层展开目录，双击文件在编辑器标签页打开。
3. 编辑文件，`Cmd/Ctrl+S` 保存；文件被外部改动时拒绝静默覆盖。
4. 在变更列表里逐文件看工作区与 `HEAD` 的差异，勾选暂存、写提交信息、提交。
5. 打开终端，在会话工作目录下执行命令。
6. 新建一个运行配置（如 `pnpm dev`），一键启动并在输出面板查看日志、随时停止。
7. 全局搜索文本，结果按文件聚合，点击直达行号。
8. 底部 Problems 面板汇总语法/lint/类型诊断，点击跳转。

### 1.3 范围边界（做）

- 单根工作区：以会话 `cwd` 为根，可浏览其子树。
- 文件级完整 CRUD：新建、读取、写入、重命名、删除、复制（宿主 `ctx.fs` 不含后三项，需自建）。
- 文本编辑、保存、外部改动冲突检测。
- 三种差异来源：工作区 vs `HEAD`、任意两提交、任意两文件。
- Git 全量常用操作：状态、变更、暂存、提交、分支、标签、stash、历史、图谱、fetch/pull/push、合并、变基、cherry-pick、reset、冲突标记。
- 终端多实例、shell 选择、重连。
- 运行配置：命令定义、一键启动、输出流、停止、历史。
- 代码理解：结构大纲、全局搜索、TODO、书签、问题汇总。

### 1.4 明确不做（Non-goals）

| 不做 | 理由 |
|---|---|
| 断点调试 / DAP | 需要调试协议宿主与适配层，超出本轮范围，且无法复用宿主任何服务 |
| LSP 语义能力（跳转定义、引用查找、补全、重构） | 需要长驻语言服务器进程管理器与会话级作用域，宿主无对应服务；自建等于重写半个 IDE 后端 |
| 多根 / 多模块工作区 | 宿主会话只有一个 `cwd`，`workspaceFiles.list` 严格限制在工作区内 |
| 数据库工具窗口、Profiler、Gradle/Maven 面板 | IDEA 生态专属，与 DSH 会话模型无关 |
| HTTP Client、UI Designer、Diagrams | 同上 |
| 远程开发（SSH / Dev Container） | 宿主 subprocess 为本地提供方，无远程执行世界 |
| 二进制 / Office 文档编辑 | 宿主只提供只读预览渲染（`sidebar-documentpreview`），写回需要格式级实现 |

> 上述不做项若后续需要，应作为新版本设计文档（v2）单独立项，不得在本版本执行步骤中顺手引入。

## 二、宿主能力盘点（事实依据）

本节是架构的物理约束来源。所有结论均来自宿主包文档与类型，不靠推测。

### 2.1 宿主侧服务（插件 host 半可用）

| 能力 | 服务 | 可用接口 | 关键限制 |
|---|---|---|---|
| 文件读写 | `ctx.fs` | `resolve` / `stat` / `readText` / `streamText` / `readBytes` / `readByteRange` / `listDir` / `watch` / `writeText` / `editText` | **没有删除、重命名、复制、递归、glob、搜索**；变更操作只支持文本，二进制写入不支持 |
| 子进程 | `ctx.subprocess` | `resolveExecutable` / `spawn` / `spawnTerminal` / `inspectActivity` | `argv` 不经 shell；环境被清洗（移除 `DSH_*` 与凭据类变量），git 凭据需显式转发 |
| HTTP 路由 | `ctx.webServer` | `register({ kind: 'exact' \| 'prefix', path, handler })` | 插件需自行做回环 / 同源校验 |
| 改动摘要 | `ctx.workspaceChanges` | `summary(sessionId, seq)` / `diff(sessionId, seq, index, signal)` | 仅随 Host 进程存活；Host 重启后历史对比不可用 |
| index.html 注入 | `webserver/index-inject` 事件 | 注入 `<script>` 到 `head` | 只支持 head 内联脚本 |

### 2.2 客户端侧服务（插件 client 半可用）

| 能力 | 接口 | 关键限制 |
|---|---|---|
| 插槽注册 | `ctx.slots.register({ name, key, ... }, Component)` + `useTabInfo()` | 同一 single 插槽按 `priority` 取最低者渲染 |
| 右侧栏 tab 类型 | `ctx.sidebarRightTabs.register({ id, kind, patterns, priority, canOpen, title, guide, keepMounted })` | 一个 kind 最多一份 builtin + 一份 extension；`id` 全局唯一，重复注册抛错 |
| 右侧栏导航 | `ctx.sidebarRight.openResource` / `openTab` / `close` / `active` / `focus` / `split` / `float` / `dock` / `toggleExpanded` / `toggleFullscreen` | 最多两格，默认均分；宽度不足时不允许分栏 |
| 工作区文件 | `ctx.remote.workspaceFiles`：`read` / `stat` / `readBytes` / `list` / `changes` | `list` 与目录监听限定工作区内；`maxEntries` 2000；页 `maxLines` 5000；`maxFileBytes` 32 MiB；**不提供写** |
| 终端 | `ctx.remote.terminal`：`environment` / `shells` / `list` / `create` / `retain` / `attach` / `rename` / `close` | 每会话 `maxTerminals` 8；`scrollback` 1000 行；同一时刻仅一个连接可写 |
| 资源模型 | `ctx.resources` + `useResource<'file'>(address)` | 地址形如 `dsh-resource://file/session/<sessionId>/<path>` |
| 语言包 | `ctx.locale.register(namespace, locale, dict)` / `bind(namespace)` | 按命名空间隔离 |
| 远程调用 | `ctx.remote.<namespace>` | 结果统一为 `{ ok, value, error }` |

### 2.3 可用的界面插槽（实测）

| 插槽 | 用途 | 来源验证 |
|---|---|---|
| `conversation.view` | 整块主对话区切换为自定义视图（「对话 / 轨迹」同级标签） | `dsh-ide-git` 使用 |
| `conversation.input.left` | 输入框工具条左侧 | `dsh-ide-git` 使用 |
| `sidebar.right.pane.tab` | 右侧栏 tab 正文（按 `key` 对齐 tab 类型 id） | 宿主 `sidebar-right` 文档 |
| `sidebar.right.pane.tab.title` | 右侧栏 tab 标题 | 同上 |
| `sidebar.right.tab.guide.entry` | 右侧栏引导页入口胶囊 | 同上 |
| `sidebar.right.tab.menu.item` | tab 右键菜单项 | 同上 |
| `settings.section` | 设置页分区 | `dsh-all-in-one` 使用 |
| `shell.overlay` | 全局浮层（模态框） | `dsh-all-in-one` 使用 |
| `sidebar.workspaces.session.row.action` | 会话行悬停操作 | `dsh-all-in-one` 使用 |

### 2.4 能力缺口（必须自建）

| 缺口 | 影响 feature | 自建方案 |
|---|---|---|
| 文件删除 / 重命名 / 复制 / 递归遍历 / glob | 项目树、搜索、运行配置 | 宿主侧用 `ctx.subprocess` 调 `/bin/rm`、`/bin/mv`、`/bin/cp`，或直接用 `node:fs/promises`；递归遍历在宿主侧 `readdir` 自行实现 |
| 文件写入的客户端通道 | 编辑器保存 | 宿主侧开 `POST /dsh-ide/api/fs/write` 路由，客户端经 `fetch` 调用 |
| 目录变更的批量监听 | 项目树自动刷新 | `ctx.fs.watch` 只报直接子项，需按已展开目录逐个挂监听并在卸载时回收 |
| 终端以外的长驻进程（dev server） | 运行配置 | `ctx.subprocess.spawn` + 输出收集器；进程句柄登记进宿主侧注册表 |
| 代码高亮 / diff 渲染 / 分栏布局 | 编辑器、差异、工作台 | 自建，编辑器与高亮走懒加载 chunk |
| 底部面板 | 终端、运行、Problems、搜索 | 宿主无底部插槽，自绘在工作台容器内 |

## 三、总体架构

### 3.1 双半结构

```
dsh-ide/
├── src/
│   ├── host/                 宿主半（Node 侧）
│   │   ├── index.ts          入口：聚合 feature host，注册路由
│   │   ├── routes/           路由注册与分发
│   │   ├── fs-service.ts     文件 CRUD、递归遍历、搜索（补 ctx.fs 缺口）
│   │   ├── git-service.ts    git 命令封装（argv 数组，不经 shell）
│   │   ├── run-service.ts    进程登记、输出缓冲、终止
│   │   └── registry.ts       feature host 注册表
│   └── client/               客户端半（浏览器侧）
│       ├── index.tsx         入口：注册插槽与 tab 类型
│       ├── shell/            工作台外壳
│       ├── features/         各功能，自包含
│       ├── common/           跨 feature 纯逻辑
│       ├── components/       跨 feature UI
│       └── types/            宿主 API 类型声明
├── locale/                   插件标题与描述
├── doc/                      设计与计划文档
└── build.ts                  构建脚本
```

**分层依赖方向（严格单向）**：

```
types ← common ← components ← features ← shell ← index
```

feature 不得反向依赖 shell 的具体实现，只能依赖 `shell/contract`（契约）与公共层。

### 3.2 与 all-in-one 的关系

采纳 all-in-one 验证过的三条工程约定，但不照抄其 feature 契约：

| 约定 | 采纳 | 差异 |
|---|---|---|
| 功能自包含，壳子零功能 | ✅ | 同 |
| feature 目录内自带 locales、entry、view、host | ✅ | 同 |
| 装配清单（`features/index.ts`、`features/host.ts`）只列导出 | ✅ | 同 |
| feature 契约形态 | ❌ 不照抄 | all-in-one 是「设置页网格卡片」，只有 `entry`/`page`/`switch`；IDE 的 feature 是**工具窗口 / 底部面板 / 编辑器视图 / 状态栏项 / 纯服务**五类，契约需重新定义 |
| 渲染位置 | ❌ 不同 | all-in-one 渲染在设置页网格；IDE 渲染在主区 View 或右侧栏 tab |

### 3.3 feature 契约

定义位置：`src/client/shell/contract.ts`。

```ts
/**
 * IDE feature 的槽位形态。
 *
 * 按「渲染到哪里」分类，而不是按「有没有页面」分类：
 * IDE 的功能绝大多数没有独立页面，而是常驻在某个槽位里。
 */
export type FeatureSlot =
  | 'toolWindow'   // 左侧竖排工具窗口（项目、Git、TODO、书签…）
  | 'bottomPanel'  // 底部面板页签（终端、运行、Problems、搜索）
  | 'editorTab'    // 编辑器区的标签类型（文件、差异、欢迎页）
  | 'statusBar'    // 状态栏条目
  | 'service'      // 无 UI，只在宿主/客户端注册后台能力

/** feature 定义；由 shell 的注册表校验后装配。 */
export interface IdeFeature {
  /** 唯一标识，同时作为语言 key 前缀与持久化 key */
  id: string
  /** 槽位形态；决定 shell 从哪个字段读取组件 */
  slot: FeatureSlot
  /** 中英文文案，shell 统一加 `<id>.` 前缀注册 */
  locales: LocaleDictionaries
  /** 排序权重，越小越靠前，默认 100 */
  order?: number
  /** toolWindow / bottomPanel 的显示图标（自带 SVG，不依赖 ui-primitives） */
  icon?: () => JSX.Element
  /** 工具窗口与底部面板的主体 */
  view?: ComponentType<FeatureViewProps>
  /** 编辑器区标签类型：提供地址匹配与渲染 */
  editor?: EditorContribution
  /** 状态栏条目 */
  status?: ComponentType<FeatureStatusProps>
  /** 宿主侧扩展（路由、进程、监听） */
  host?: FeatureHostExtension
}
```

约束：

- 五个槽位字段互斥：`slot` 为 `toolWindow` / `bottomPanel` 时必须给 `view`，为 `editorTab` 时必须给 `editor`，为 `statusBar` 时必须给 `status`，为 `service` 时必须给 `host`。
- 契约校验不通过的定义被注册表跳过并记日志，单个 feature 出错不影响整个工作台。
- 新增必填字段时必须同步更新校验函数 `isIdeFeature`。

### 3.4 工作台外壳

`shell/` 只负责骨架，不承载业务：

| 文件 | 职责 |
|---|---|
| `contract.ts` | feature 契约与类型 |
| `registry.ts` | feature 校验、排序、按槽位分组 |
| `Workbench.tsx` | 三区布局容器（左工具条 / 中编辑区 / 右工具条 + 底部面板 + 状态栏） |
| `ToolWindowBar.tsx` | 左侧竖排按钮条，按可用高度收纳到「更多」 |
| `EditorArea.tsx` | 标签页条 + 视图容器，支持横向 / 纵向分栏 |
| `BottomPanel.tsx` | 底部面板页签，高度可拖拽 |
| `StatusBar.tsx` | 状态栏，读取各 feature 的 `status` 贡献 |
| `CommandRegistry.ts` | 命令定义、快捷键绑定、命令面板 |
| `LayoutStore.ts` | 布局状态（各panel 尺寸、激活视图、分栏） |
| `EditorStore.ts` | 打开的文件与游标位置 |
| `services/` | feature 间通信总线（事件、共享状态），避免 feature 相互 import |

### 3.5 UI 落位方案

工作台有两种承载面，同一份组件树，由外层容器适配：

| 承载面 | 注册方式 | 适用 | 面积 |
|---|---|---|---|
| **主区视图**（首选） | `ctx.slots.register({ name: 'conversation.view', key: 'dsh-ide' }, Workbench)` | 日常编码 | 占满主对话区 |
| **右侧栏 tab** | `ctx.sidebarRightTabs.register({ id: 'dsh-ide:workbench', kind: 'ide' })` + `slots.register({ name: 'sidebar.right.pane.tab', key: 'dsh-ide:workbench' })` | 边聊边看 | 窄而高，布局自动降级 |

窄屏降级规则：容器宽度 < 768px 时隐藏左工具条，工具窗口改为顶部分段控件；底部面板改为可折叠抽屉。

> 主区视图与右侧栏 tab 共用同一个 `Workbench` 组件，**不写两套布局**。布局由容器用 `ResizeObserver` 量自身尺寸决定（宽度主导，高度不否决），与 `dsh-ide-git` 的做法一致。

### 3.6 状态持久化

| 数据 | 存储位置 | key | 说明 |
|---|---|---|---|
| 工作台布局 | `localStorage` | `dsh-ide.layout.v1.<sessionId>` | 各面板尺寸、激活的工具窗口、底部分栏比例、当前承载面 |
| 打开的文件与游标 | `localStorage` | `dsh-ide.editors.v1.<sessionId>` | 文件地址、光标行列、滚动位置、未保存草稿标记 |
| 运行配置 | `$DSH_HOME/dsh-ide/run-configs.json` | — | 跨会话共享，按工作目录分组 |
| 全局设置 | `$DSH_HOME/dsh-ide/settings.json` | — | 编辑器字号、自动保存、diff 上下文行数、终端 shell |
| 项目索引缓存 | `$DSH_HOME/dsh-ide/cache/<hash>/` | — | 文件清单与 TODO 扫描结果，可随时删除重建 |

约束：

- 所有 localStorage key 均带 `.v1.` 版本段，格式变更时升版本并丢弃旧值，不做迁移。
- 存储失败不影响内存态可用（沿用宿主侧同类容错策略）。
- **不在启动期读取这些存储**：只在工作台挂载时读。

## 四、Feature 清单

阶段标记：**P0** 基础设施 / **P1** 浏览 / **P2** 编辑 / **P3** 差异 / **P4** 终端 / **P5** Git / **P6** 运行 / **P7** 检索与分析 / **P8** 打磨。

### F01 workbench 工作台外壳（P0）

| 项 | 内容 |
|---|---|
| 槽位 | `service`（外壳本体不注册为 feature，由 `shell/` 实现；此处登记为 feature 以参与清单与分期） |
| 职责 | 三区布局、面板拖拽、快捷键注册、命令面板、模态浮层 |
| 输入 | 各 feature 按槽位注册的定义 |
| 输出 | 渲染骨架 + 布局状态 + 命令执行入口 |
| 行为 | ① 首屏渲染左工具条 + 空编辑区 + 状态栏；② 点击工具条按钮切换左侧面板显隐；③ 拖拽分隔条调整面板尺寸并持久化；④ `Cmd/Ctrl+Shift+P` 打开命令面板 |
| 边界 | 外壳不感知任何 feature 的 id、文案或业务逻辑；不内置统一卡片模板 |

### F02 project-tree 项目树（P1）

| 项 | 内容 |
|---|---|
| 槽位 | `toolWindow` |
| 输入 | 会话 `cwd`；目录展开事件；文件系统变更通知 |
| 输出 | 树节点列表；打开文件 / 打开差异的命令调用 |
| 行为 | ① 根为会话 `cwd`，逐层懒加载（首次展开时才列目录）；② 目录优先、自然序、忽略大小写排序；③ dotfiles 默认隐藏，可开关；④ 文件按扩展名着色图标；⑤ 承接 Git 状态着色（F08 提供状态映射）；⑥ 右键菜单：打开、在编辑器中打开、重命名、删除、复制路径、新建文件、新建目录、在文件中查找 |
| 边界 | 不显示工作区根之外的路径；目录条目超过 2000 项时显示截断标记；不实现拖拽上传 |
| 宿主能力 | `remote.workspaceFiles.list`（读）、`ctx.fs.watch`（监听）、`POST /dsh-ide/api/fs/*`（写操作） |

### F03 editor 编辑器（P2）

| 项 | 内容 |
|---|---|
| 槽位 | `editorTab` |
| 输入 | 文件地址 `dsh-resource://file/session/<sessionId>/<path>`；保存命令；外部变更通知 |
| 输出 | 编辑缓冲区、脏标记、保存结果 |
| 行为 | ① 多标签页、可拖拽排序、中键关闭；② CodeMirror 6，按扩展名加载语言支持（懒加载 chunk）；③ 行号、当前行高亮、括号匹配、自动缩进；④ `Cmd/Ctrl+S` 保存，`Cmd/Ctrl+F` 查找替换；⑤ 外部改动检测：保存前比对版本，不一致则弹出选择（覆盖 / 重新加载 / 另存）；⑥ 未保存关闭时二次确认；⑦ 大文件（> 2 MiB）降级为只读预览 |
| 边界 | 不做 LSP 补全与跳转；不做多光标之外的重构；二进制文件交给只读预览；编码固定 UTF-8，不做转码 |
| 宿主能力 | `remote.workspaceFiles.read`（分页读）、`POST /dsh-ide/api/fs/write`（写） |

## 六、宿主侧接口契约

所有客户端到宿主的写操作与 git 操作走插件自己的 HTTP 路由，统一前缀 `/dsh-ide/api`。

### 6.1 通用约定

- 请求体与响应体均为 JSON，字段 camelCase。
- 统一信封：`{ ok: true, value }` / `{ ok: false, error: { code, message } }`。
- 错误码英文大写，展示文案由客户端按 locale 翻译。
- **回环校验**：只接受本机回环地址，或带 `Sec-Fetch-Site: same-origin` / `same-site` 的请求；不满足直接 403。
- 所有路径参数在宿主侧解析为绝对路径后，必须校验位于会话工作区内（写操作强制，读操作沿用宿主 `ctx.fs` 的权限策略）。

### 6.2 路由清单

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/dsh-ide/api/fs/list` | 列目录（含 dotfiles 与截断标记） |
| `POST` | `/dsh-ide/api/fs/write` | 写文件，带版本防护 |
| `POST` | `/dsh-ide/api/fs/create` | 新建文件 / 目录 |
| `POST` | `/dsh-ide/api/fs/rename` | 重命名 / 移动 |
| `POST` | `/dsh-ide/api/fs/delete` | 删除（进回收站或直接删除，见 6.3） |
| `POST` | `/dsh-ide/api/fs/copy` | 复制 |
| `GET` | `/dsh-ide/api/fs/stat` | 文件元信息与版本 |
| `POST` | `/dsh-ide/api/git/exec` | 受控 git 命令分发（方法表，非任意命令） |
| `POST` | `/dsh-ide/api/run/start` | 启动运行配置 |
| `POST` | `/dsh-ide/api/run/stop` | 停止进程 |
| `GET` | `/dsh-ide/api/run/output` | 输出流（分页 / 增量） |
| `GET` | `/dsh-ide/api/run/list` | 进程清单与状态 |
| `POST` | `/dsh-ide/api/diagnose` | 运行诊断命令并解析结果 |

> `/dsh-ide/api/git/exec` 不接受任意命令串，只接受方法名 + 结构化参数，方法表由宿主侧白名单定义。

### 6.3 安全细则

- 删除：默认移动到 `$DSH_HOME/dsh-ide/trash/<timestamp>/`，保留 7 天；配置可改为直接删除（需二次确认文案不同）。
- 写入：先写临时文件再 `rename` 原子替换。
- 版本防护：请求携带 `expectedVersion`，与当前版本不一致返回 `STALE_FILE`，客户端弹出覆盖/重载选择。
- 命令：全部 `argv` 数组，参数校验（绝对路径、ref 不以 `-` 开头、无控制字符、路径不越出仓库）。

## 七、性能约束

以下为硬约束，适用于所有 feature。

### 7.1 启动期

- `apply()` 及其同步分支内禁止扫描目录、读大文件、解析缓存。只注册路由与元数据。
- 重活推迟到用户打开工作台或触发对应动作时。
- 客户端 bundle 启动体积目标 ≤ 200 KB（gzip 前），CodeMirror、xterm、diff 渲染、语言高亮全部拆为独立 chunk，首次使用时动态 `import()`。

### 7.2 稳态

- 所有 `setInterval` / `setTimeout` / 事件订阅必须在 `ctx.effect` 的清理函数里撤销；长间隔定时器 `unref()`。
- 文件监听按需挂载、及时回收，事件合并窗口 200ms。
- 终端输出、运行输出走增量拉取，不在客户端保留全量历史。
- 大文件阈值：编辑器 2 MiB、diff 2 MiB、搜索单文件 1 MiB。

### 7.3 验证要求

- 改动涉及启动链路、监听器、宿主注册时，必须实测「插件启用 / 禁用」的冷启动耗时与 CPU 采样，给出具体数字，不写「明显变快」。
- 冷启动连测至少 3 次，取中位数。

## 九、风险与限制

| 风险 | 影响 | 应对 |
|---|---|---|
| 宿主 `ctx.fs` 无删除/重命名 | 项目树 CRUD 需自建 | 宿主侧自建 fs 服务，直连 `node:fs/promises`，并做工作区边界校验 |
| `remote.workspaceFiles.list` 限工作区内、上限 2000 项 | 大目录截断 | 项目树按需展开；搜索走宿主侧自建递归，不用该接口 |
| 宿主 `maxTerminals` 8 / 会话 | 终端页签数量受限 | UI 显式提示上限并引导关闭 |
| 宿主每个 kind 只能有一份 extension 注册 | 与第三方终端/Git 插件可能冲突 | 本插件用独立 kind（`ide`、`ide-editor`），不复用 `terminal`/`files`/`git`，避免接管冲突 |
| `ctx.workspaceChanges` 仅进程内存活 | 历史差异在 Host 重启后不可用 | 差异一律走自建 git 服务，不依赖该服务 |
| 主区视图同一时刻只能激活一个 | 无法边看对话边看 IDE 全宽 | 提供右侧栏承载面作为并排方案 |
| 宿主插槽结构变更 | 注册失败 | 所有插槽注册放在 `ctx.inject` 回调中，服务缺失时只跳过，不影响插件其它部分 |

## 十、验收总纲

本设计完成的最低可验收状态：

1. 会话内可打开工作台，能看到项目树、编辑器、底部面板、状态栏四区。
2. 能浏览、打开、编辑、保存一个真实文件，退出重进后布局与打开的文件恢复。
3. 能看到工作区变更并逐文件查看差异，能暂存、提交。
4. 能在终端里执行命令，刷新页面后终端存活。
5. 能新建运行配置并启动一个真实 dev server，看到日志并能停止。
6. 插件禁用或删除后，DSH 其余功能不受影响。
