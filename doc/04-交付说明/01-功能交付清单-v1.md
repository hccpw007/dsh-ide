## 二、与设计的差异

| 项 | 设计 | 实现 | 原因 |
|---|---|---|---|
| 目录读取来源 | `remote.workspaceFiles.list` | 插件自己的 `/fs/list` | 项目树的 CRUD、Git 着色、隐藏文件开关都用同一套工作区边界；与编辑器、Git、搜索共用一条路径语义 |
| 文件写入 | `POST /fs/write`（设计一致） | 同设计，带 `expectedVersion` 乐观锁 | — |
| 文件监听 | `ctx.fs.watch` | 客户端在保存 / Git 操作 / 新建删除后广播失效通知，目录按需重读 | 当前宿主 `ctx.fs` 没有 `watch` 原语（见其 README「十二个原语」），轮询会违背性能约束 |
| 差异引擎 | 运行时直接用 jsdiff | jsdiff 走 `diff-kernel` 懒加载 chunk | 主 bundle 需要控制在 200 KB 内 |
| 删除恢复 | 回收站保留 7 天 | 删除进回收站并从客户端触发过期清理；恢复入口只给出批次路径 | 设计要求的恢复 UI 未列入本轮验收项，预留了 manifest |
| 运行配置进程 | `ctx.subprocess.spawn` | `node:child_process.spawn` + `[shell, '-lc', command]` | 宿主 `ctx.subprocess` 不保证在插件宿主半可用；实现与设计 11.1 的 argv 形态一致 |
| 诊断命令 | 同设计 | 同设计，固定 `[shell, '-lc', command]` | — |

## 三、验收方式

全部验收项通过「本地 dev profile + 无头 Chrome 真实操作」验证：

1. `npm run typecheck`、`npm run build` 通过，产出 `index.js`、`client.js`、`chunks/*.js`；
2. 主区「IDE」页签渲染工作台，项目树显示会话 cwd；
3. 打开 Markdown / TypeScript 文件，CodeMirror 正常渲染并高亮；
4. 编辑后 `Cmd+S` 落盘，`/fs/write` 返回新版本；
5. Git 面板列出真实变更，点击文件打开并排差异；
6. 历史、分支、大纲、TODO、搜索、问题面板均能取到真实数据；
7. 右侧栏「IDE」入口打开同一份工作台，窄容器（< 768px）下工具窗口改为顶部分段控件；
8. 命令面板（`Cmd+Shift+P`）与 `Cmd+J` 快捷键可用；
9. `curl` 直接访问 `/dsh-ide/api/*` 返回统一信封，跨站 Origin 返回 403。

## 四、已知限制

- 终端依赖宿主 `remote.terminal`：当同一会话被另一个宿主进程持有时，创建会返回宿主侧的写入租约错误（两个 host 同时打开同一会话时的环境限制）。
- 文本编辑固定 UTF-8，不支持转码；二进制文件不提供编辑器视图。
- 大纲与 TODO 是正则级近似，不具备语义准确性（设计 D4 已列为 Non-goals）。
- 差异对比以「提交版本 ↔ 工作区」为主，提交之间的整树差异需要逐文件打开。
